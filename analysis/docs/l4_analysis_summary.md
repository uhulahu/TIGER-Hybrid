# L4 Structured Codebook 分析汇总

> K0 (RQ-KMeans + random extra token) vs K2 (RQ-KMeans + structured L4, λ=10)，Beauty/test (N=22,363, beam=30)。
> 两者前三层 SID 完全相同，仅 L4 分配方式不同。
> 来源 notebook: `analysis/l4_analysis.ipynb`

---

## 背景

标准 TIGER 使用 4-token SID：前三层由 RQ-KMeans / RQ-VAE 逐层量化，第四层为 extra token——对共享同一 (L1,L2,L3) 前缀的碰撞 item 随机编号（0, 1, 2, …），不同碰撞桶之间无共享语义。

我们使用 **Structured L4 codebook** 替代随机 extra token：冻结前三层码本后，使用 constrained KMeans 对所有 item 的第三层残差训练一个 256-code 的 L4 码本，使用量化损失并对碰撞 item 进行 λ 倍加权（K2 使用 λ=10）。碰撞桶内通过 Hungarian 算法强制单射分配，singleton item 做普通 argmin。同一 L4 码字可被不同桶复用，形成跨桶一致的语义结构。

---

## 分桶

测试集中每个用户的 target item 按前三层前缀查 catalog，确定属于 singleton bucket（桶内仅此一个 item，85.1%）还是 collision bucket（桶内多个 item 共享同一 L1+L2+L3 前缀，14.9%）。collision bucket 进一步按桶大小细分：

| Bucket | N | 占比 |
|--------|---:|:----:|
| All | 22,363 | 100.0% |
| Singleton (size=1) | 19,020 | 85.1% |
| Collision (size>1) | 3,343 | 14.9% |
|   size=2 | 2,508 | 11.2% |
|   size=3-4 | 656 | 2.9% |
|   size≥5 | 179 | 0.8% |

> **分析逻辑**：collision bucket 是 structured L4 消歧功能的直接作用对象；singleton bucket 用于检测 L4 是否提供了超越纯消歧的语义价值。如果 singleton 的 Δ > 0，说明 structured L4 不只是随机编号的替代品——跨桶一致的 L4 码字提供了可学习的预测信号。

### 关键发现

1. **总体增益主要由 singleton 贡献，collision 的净命中提升有限**。按 R@20 的 Δ × N 估算实际命中数变化：
   - Singleton：19,020 × (+0.0013) ≈ **+25** 个命中
   - Collision：3,343 × (+0.0006) ≈ **+2** 个命中
   - 总体：约 +27 个命中
   
   碰撞桶内部进一步分解：
   - size=2：2,508 × (−0.0040) ≈ **−10** 个命中
   - size=3-4：656 × (+0.0122) ≈ **+8** 个命中
   - size≥5：179 × (+0.0223) ≈ **+4** 个命中

   Structured L4 的总体收益主要来自 singleton 样本（占 85%）的微小正向偏移，而非直接来自 collision 消歧。

2. **大桶中观察到更明显的相对增益，但样本量小，仅为趋势性现象**。size=3-4（N=656，+8 命中）和 size≥5（N=179，+4 命中）的 Δ 在相对值上显著，但绝对命中数很小。size≥5 仅 179 个样本，不能据此建立「桶越大收益越大」的稳定单调关系；size=2 的下降也仅约 10 个样本。需 paired bootstrap 或 McNemar 检验确认统计显著性。

3. **size=2 场景 K2 Recall 负向**（−0.0040）：可能原因是二选一的简单消歧场景中，随机编号已足够区分，而 structured L4 引入了不必要的分布复杂度。但由于绝对命中变化仅约 10 个，也可能是抽样波动。

4. **Recall 和 NDCG 增长幅度接近**：说明 structured L4 的收益主要来自覆盖（把更多正确 item 拉进 beam），而非排序精度的提升。

**指标说明**：
- **L4_CE**：给定 ground-truth L1+L2+L3 作为 decoder prefix，T5 预测 L4 token 的交叉熵（仅在 256 个合法 L4 token 上计算，排除模型误预测到 L1/L2/L3 范围的影响）。注意代码中使用 `np.log`（自然对数），因此单位为 **nats** 而非 bits（除以 ln 2 后才为 bits）
- **TF_Acc (Teacher-forcing 条件准确率)**：Teacher-forcing 条件下 L4 预测准确率。decoder 前三步直接喂正确答案，隔离「前三层本身对不对」的影响，单纯测量给定正确前缀后 L4 的可预测性。结构化的 L4 在困难场景（size≥3）中是否比随机编号更可预测？
- **BeamCondAcc (Beam-search 条件准确率)**：Beam search 完整搜索过程中，在 prefix3 已命中的条件下，L4 是否也命中。反映完整推理过程中正确 suffix 的存活率，正确 suffix 是否最终留在 top-K。

### 关键发现

1. **Structured L4 并没有让 L4 整体更容易预测**。K2 相比 K0：
   - Overall TF_Acc：0.9236 < 0.9458
   - Collision TF_Acc：0.6366 < 0.6404
   - BeamCondAcc：0.9409 < 0.9453
   - L4 CE 全面更高（All: 0.3244 vs 0.1380 nats）
   
   Structured L4 扩大了标签支持集（256-way vs ~10-way），提高了 L4 任务复杂度，CE 更高是预期内的代价。不是「structured L4 让 L4 更容易预测」，而是「尽管 L4 更难预测，排序结果仍略有改善」。

2. **仅在 size=3–4 和 size≥5 的部分困难碰撞桶中，TF accuracy 显示出潜在优势**：size≥5 中 K2 的 TF_Acc 高于 K0（0.4302 vs 0.3855），size=3–4 中略高（0.5229 vs 0.5168）。但这些桶的样本量较小（179 和 656），需谨慎解读。在更需要区分多个 item 的场景中，语义结构可能带来可学习性收益，但当前证据不足以建立稳定结论。

3. **K2 的 CE 代价被最终排序效果所补偿**：尽管 L4 预测难度增加，K2 在表 1 的 Recall 和 NDCG 上仍略高于 K0。说明模型学到的 L4 分布虽然交叉熵更高，但排序质量并未受损。

4. **K0 在 singleton 中的 TF_Acc 接近 1.0**（0.9995）：random extra token 在 singleton 桶中几乎总是 code 0，模型学到了「singleton → code 0」的平凡映射，CE 仅 0.0033 nats。

## 表 3：L4 Token 分布 — 码本利用率与熵

| Model/Source | N | Used/256 | H (bits) | H_norm | K_eff |
|---|---|---|---|---|---|
| K0 catalog (all) | 12,101 | 10 | 0.4568 | 0.0571 | 1.4 |
| K0 catalog (collision-only) | 1,556 | 10 | 1.6234 | 0.2029 | 3.1 |
| K2 catalog (all) | 12,101 | 256 | 6.6664 | 0.8333 | 101.6 |
| K2 catalog (collision-only) | 1,556 | 156 | 6.4619 | 0.8077 | 88.1 |
| K0 predicted (all) | 22,363 | 8 | 0.5322 | 0.0665 | 1.4 |
| K0 predicted (collision) | 3,343 | 8 | 1.5444 | 0.1931 | 2.9 |
| K2 predicted (all) | 22,363 | 230 | 6.6100 | 0.8263 | 97.7 |
| K2 predicted (collision) | 3,343 | 127 | 6.2623 | 0.7828 | 76.8 |
| K0 test target (all) | 22,363 | 9 | 0.5136 | 0.0642 | 1.4 |
| K0 test target (collision) | 3,343 | 9 | 1.5748 | 0.1969 | 3.0 |
| K2 test target (all) | 22,363 | 237 | 6.6156 | 0.8269 | 98.1 |
| K2 test target (collision) | 3,343 | 141 | 6.2867 | 0.7858 | 78.1 |

**指标说明**：
- **Used/256**：被用到（分配/预测/出现）的码字数量（最大 256）
- **H (bits)**：香农熵。0 = 只有一个码字被用；理论最大值 log₂(256) = 8 bits
- **H_norm**：H / 8，归一化到 [0, 1]
- **K_eff**：2^H，等效均匀码字数。例如 H=6 bits → 等效于均匀使用 64 个码字

**三组行分别回答**：tokenizer 是否充分使用了 L4 码本（catalog）、模型是否在利用完整码本空间（predicted）、测试目标本身是否有偏斜（test target）。

### 关键发现

1. **K0 的低利用率是设计必然，而非 codebook collapse**。K0 的 extra token 并非学习得到的 256-code 码本，而是按桶内首次碰撞顺次编号——最大碰撞桶约 10 个 item，因此最多只需要 10 个 extra token；singleton 统一使用 code 0。低熵（H=0.46 nats，注意此处 H 用 log₂ 计算故为 bits）和低利用率是其设计结果，不存在「本该使用完整码本却退化」的问题。

2. **K2 将 L4 标签空间扩展为 256-way 离散分布**：全部 256 个码字均被使用，H=6.67 bits（理论最大值 log₂(256)=8 bits 的 83%），K_eff=101.6——等效于均匀使用 102 个码字。与 K0 的 ~10-way 相比，K2 显著扩大了 L4 的信息容量。注意 256 是离散码字数量，prototype 向量维度为 32，不是 256 维表示空间。

3. **Catalog → predicted → test target 三层面分布高度一致**：K2 的 H 在三层面均在 6.5-6.7 bits 之间，说明模型预测的 L4 边缘频率与真实标签频率比较匹配，没有只预测少数热门 code。但这只证明了频率校准，不能单独证明 L4 code 具有跨桶语义——要确认语义性还需进一步验证：（a）同一 L4 code 下 residual 的簇内距离；（b）同 code item 的内容相似度是否高于随机组；（c）L4 token 的跨桶邻域一致性。

4. **Collision-only 分布与 all 接近**：K2 的 collision-only catalog H=6.46 vs all H=6.67，差距仅 0.21 bits。码字的丰富使用惠及了真正需要消歧的碰撞 item，而非仅给 singleton 做装饰。

- **FullBeam**：从完整四层 beam 剥离 L4 后计算，受 sibling（同一前缀不同 L4 的路径）挤占 slot 影响，作为辅助参考

K0 和 K2 的前三层 catalog 完全相同，唯一的训练差异在于 L4 token 的标签分布。如果 K2 的 Prefix-3 Recall/NDCG 高于 K0，说明改变 L4 标签结构影响了对 L1-L3 也有用的那部分模型参数——T5 decoder 在所有 4 个生成步上共享同一套 Transformer 参数，L4 端的训练信号变化会同时更新 L1-L3 预测所用的参数。

### 关键发现

1. **K2 的 Prefix-3 Recall 一致高于 K0**：Direct Recall@10 Δ = +0.0028（相对提升 4.5%）。这是改变 L4 标签结构后，前三层排序改善的一致性现象。两者前三层 catalog 完全相同，唯一的训练差异是 L4 token 的标签分布，因此该改善支持「structured L4 通过影响所有生成步共享的 decoder 参数，间接改善了前缀排序」的假设。

2. **改善集中在排序（K=5-10 区间），top-1 无差异**：K=10 处 Recall Δ = +0.0028，而 K=5（+0.0009）和 K=1（−0.0001）增幅较小。Structured L4 将一些原本排在 11-30 的正确前缀拉进了 top-10，但不改变最高置信度的预测——top-1 仍然由前三层的模型能力主导。

3. **Direct 和 FullBeam 趋势一致，但 FullBeam 增益更大**：FullBeam 的 Recall Δ 在 K=20 和 K=30 处大于 Direct（+0.0025, +0.0023 vs +0.0008, +0.0013）。一种可能的解释是 structured L4 减少了 sibling 挤占（同前缀不同 L4 的 beam 路径更集中），但目前没有直接证据。验证该假设需额外统计每个样本 top-K 中：unique prefix-3 数量、每个 prefix 对应的平均 L4 sibling 数、以及同一 prefix 占用多个 beam slot 的比例。

## 总结

四个分析维度共同刻画 structured L4 相对于 random extra token 的变化：

1. **总体增益主要来自 singleton，而非 collision 消歧**（表 1）。R@20 的 +27 命中中，singleton 贡献约 +25（样本量大、微小正向偏移），collision 仅贡献约 +2。大桶（size≥3）中观察到更明显的相对增益（Δ R@20 约 +0.01~+0.02），但涉及样本仅 835 个（3.7%），绝对命中增量约 12 个——仅为趋势性现象，有待更大规模或显著性检验确认。

2. **Structured L4 并没有让 L4 更容易预测**（表 2）。K2 的 CE（nats）全面更高、TF_Acc 和 BeamCondAcc 整体略低——256-way 标签空间天然比 ~10-way 更难。仅在 size=3–4 和 size≥5 的部分困难碰撞桶中 TF_Acc 显示潜在优势，但由于样本量小（179~656），不能作为可靠结论。

3. **K0 的低 L4 利用率是顺次编号的设计必然，K2 将标签空间扩展为 256-way 离散分布**（表 3）。K0 仅需 10 个 token 覆盖最大碰撞桶，不是 codebook collapse；K2 全用 256 码字（H=6.67 bits, K_eff≈102），显著扩大了信息容量。Catalog → predicted → test target 三层面分布一致说明频率校准良好，但 L4 code 是否具有跨桶语义一致性仍需额外验证（簇内距离、同 code 内容相似度、邻域一致性）。

4. **Prefix-3 排序的一致改善是 structured L4 最有价值的发现**（表 4）。在 K0 和 K2 前三层 catalog 完全相同的条件下，K2 的 Direct Prefix-3 Recall@10 从 0.0622 提升至 0.0650（相对 +4.5%），这说明 structured L4 的收益确实不局限于最后一步。该现象支持「L4 标签结构通过影响所有生成步共享的 decoder 参数，间接改善了前缀排序」的假设。

整体上，这份分析支持保留 Structured L4，但应把它定位为全局标签结构优化带来的边际系统收益，而不是“L4 变得普遍更容易预测”或“主要解决了大桶碰撞”。
